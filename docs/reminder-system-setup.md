# Ch Composing Estamp & Tax Advisor: Tax Reminder System Setup Guide

This guide provides step-by-step instructions for configuring, deploying, and operating the automated tax reminder backend, Supabase Edge Functions, Resend email service, and admin portal.

---

## 1. Prerequisites

- [Supabase CLI](https://supabase.com/docs/guides/cli) installed (`npx supabase` or `brew install supabase/tap/supabase`)
- A [Supabase](https://supabase.com) Project
- A [Resend](https://resend.com) Account and verified domain (`chcomposing.pk` or test domain)

---

## 2. Supabase Project & Database Setup

### Step 2.1: Link your local repository to Supabase
```bash
npx supabase login
npx supabase link --project-ref your-project-ref
```

### Step 2.2: Apply Database Migrations
Run the database migration to create the tables, triggers, indexes, RLS policies, and functions:
```bash
npx supabase db push
```
Alternatively, open the Supabase Dashboard **SQL Editor** and run the contents of:
`supabase/migrations/20240916000001_tax_reminder_system.sql`.

This provisions:
- `tax_categories` (seeded with standard FBR, PRA, Corporate, and E-Stamp categories)
- `subscribers` & `subscriber_categories`
- `subscription_tokens` (hashed with SHA-256 for double opt-in)
- `tax_deadlines` (with automatic revision tracking and date-change un-verification triggers)
- `reminder_deliveries` (with composite unique constraints)
- `admin_memberships` (role-based admin access)
- `rate_limits` & `claim_reminder_deliveries()` atomic stored procedure

## 3. Creating the First Administrator

Ordinary authenticated accounts do not have admin permissions. To create your first verified administrator:

1. Create a user via Supabase Dashboard **Authentication** > **Users** > **Add User** (or let them sign up).
2. Note the user's UUID (`id`).
3. In the Supabase **SQL Editor**, grant admin authorization:
```sql
INSERT INTO public.admin_memberships (user_id, role)
VALUES ('PASTE-USER-UUID-HERE', 'admin')
ON CONFLICT (user_id) DO NOTHING;
```
Now, this user can log into the private admin area at `/admin/login`.

## 4. Resend Domain Verification & API Key

### Step 4.1: Add Domain to Resend
1. In the [Resend Dashboard](https://resend.com/domains), click **Add Domain** and enter `chcomposing.pk` (or your subdomain like `mail.chcomposing.pk`).
2. Add the DNS records generated by Resend to your domain registrar / DNS provider:
   - **SPF Record** (TXT): `v=spf1 include:amazonses.com ~all`
   - **DKIM Records** (CNAME): 3 DKIM keys provided by Resend
   - **DMARC Record** (TXT): `v=DMARC1; p=none;`
3. Click **Verify Records** in Resend until status turns **Verified**.

### Step 4.2: Generate API Key
1. Go to **API Keys** in Resend.
2. Create an API key named `ch-composing-reminders`.
3. Save the secret key (e.g. `re_123456789...`).

## 5. Configuring Supabase Edge Function Secrets

Run the following command to store backend secrets in Supabase's secure vault:

```bash
npx supabase secrets set \
  RESEND_API_KEY="re_your_api_key_here" \
  RESEND_FROM_EMAIL="Ch Composing Reminders <reminders@chcomposing.pk>" \
  SITE_URL="https://chcomposing.pk" \
  BUSINESS_TIMEZONE="Asia/Karachi" \
  CRON_SECRET="generate-a-strong-random-secret-here" \
  RESEND_WEBHOOK_SECRET="whsec_optional_webhook_secret" \
  DEVELOPMENT_MODE="false" \
  DEV_NOTIFICATION_EMAIL="usama@chcomposing.pk"
```

### Explanation of Backend Secrets:
| Secret Name | Purpose |
| :--- | :--- |
| `RESEND_API_KEY` | Resend API key for sending emails |
| `RESEND_FROM_EMAIL` | Verified sender address (e.g. `reminders@chcomposing.pk`) |
| `SITE_URL` | Base URL of your website for confirmation and unsubscribe links |
| `BUSINESS_TIMEZONE` | Timezone for calculating cutoff dates (defaults to `Asia/Karachi`) |
| `CRON_SECRET` | Secret token to authenticate scheduled daily runs |
| `RESEND_WEBHOOK_SECRET` | Secret to verify signatures of Resend bounce/complaint webhooks |
| `DEVELOPMENT_MODE` | If `"true"`, all reminder emails are redirected to `DEV_NOTIFICATION_EMAIL` |
| `DEV_NOTIFICATION_EMAIL` | Safe test recipient address when `DEVELOPMENT_MODE="true"` |

## 6. Deploying Supabase Edge Functions

Deploy the 6 Edge Functions using the Supabase CLI:

```bash
# 1. Public subscription endpoint
npx supabase functions deploy subscribe --no-verify-jwt

# 2. Public double opt-in confirmation endpoint
npx supabase functions deploy confirm-subscription --no-verify-jwt

# 3. Public unsubscribe endpoint
npx supabase functions deploy unsubscribe --no-verify-jwt

# 4. Daily reminder worker (protected by CRON_SECRET)
npx supabase functions deploy send-tax-reminders --no-verify-jwt

# 5. Admin-only test email endpoint (verifies admin JWT)
npx supabase functions deploy send-test-reminder

# 6. Resend delivery & bounce webhook
npx supabase functions deploy resend-webhook --no-verify-jwt
```

## 7. Configuring Daily Cron Schedule (Asia/Karachi 9:00 AM)

In Pakistan Standard Time (`Asia/Karachi`), 9:00 AM corresponds to **04:00 AM UTC** (`UTC+5`).

### Option A: Via Supabase pg_cron (Recommended)
Run the following SQL in Supabase **SQL Editor** to schedule the worker every morning at 09:00 AM PKT (04:00 UTC):

```sql
-- Enable required extensions
CREATE EXTENSION IF NOT EXISTS pg_cron;
CREATE EXTENSION IF NOT EXISTS pg_net;

-- Schedule daily job at 04:00 AM UTC (09:00 AM Asia/Karachi)
SELECT cron.schedule(
  'dispatch-daily-tax-reminders',
  '0 4 * * *',
  $$
  SELECT net.http_post(
    url := 'https://your-project-ref.supabase.co/functions/v1/send-tax-reminders',
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'x-cron-secret', 'YOUR_CRON_SECRET_HERE'
    ),
    body := '{}'::jsonb
  ) AS request_id;
  $$
);
```

### Option B: External Cron Provider (e.g. cron-job.org / GitHub Actions)
- **URL**: `https://your-project-ref.supabase.co/functions/v1/send-tax-reminders`
- **Method**: `POST`
- **Schedule**: `0 4 * * *` (04:00 UTC = 09:00 PKT)
- **Header**: `x-cron-secret: YOUR_CRON_SECRET_HERE`

## 8. Configuring Resend Webhook for Bounce & Spam Suppression

To automatically suppress email addresses that hard bounce or submit spam complaints:

1. Open [Resend Webhooks](https://resend.com/webhooks).
2. Click **Add Webhook**.
3. **Endpoint URL**: `https://your-project-ref.supabase.co/functions/v1/resend-webhook`
4. **Events to listen for**:
   - `email.delivered`
   - `email.bounced`
   - `email.complained`
5. Copy the Signing Secret (`whsec_...`) and update your Supabase secrets:
   ```bash
   npx supabase secrets set RESEND_WEBHOOK_SECRET="whsec_..."
   ```

## 10. Admin Workflow: Updating and Verifying Tax Deadlines

### How to add and verify deadlines:
1. Log into `/admin/login` using your administrator email and password.
2. Navigate to **Deadlines** (`/admin/deadlines`).
3. Click **Add Tax Deadline**.
4. Select the appropriate Tax Category (e.g. *Income Tax - Individuals & Salaried*).
5. Specify the Tax Period (e.g. `Tax Year 2024`) and Official Title.
6. Select the statutory deadline date (e.g. `2024-09-30`).
7. Paste the official FBR/PRA gazette or circular URL under **Official Source URL**.
8. Click **Save Deadline**.
9. **Verify the Deadline**: Click the **Verify** button next to the deadline.
   > **Note**: Automated reminder emails are **only sent for verified deadlines**. If the deadline date is ever modified in the future, verification is automatically invalidated until checked again by an administrator.

## 11. Safe Development Mode Testing

During initial staging or development:
1. In Supabase secrets, set:
   ```bash
   npx supabase secrets set DEVELOPMENT_MODE="true" DEV_NOTIFICATION_EMAIL="your-test-inbox@gmail.com"
   ```
2. Any triggered reminders will be safely diverted to `your-test-inbox@gmail.com` with a `[DEV MODE -> original@example.com]` subject prefix, completely safeguarding real subscribers.
3. Test the single-click test email feature via **Reminder Logs** > **Send Test Email**.
4. Once verified, set `DEVELOPMENT_MODE="false"`.
